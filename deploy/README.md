# تشغيل همّة على سيرفر

هذه العُدّة تشغّل همّة على سيرفر واحد بأمر واحد: المنصة، وقاعدة بيانات MySQL، وشهادة HTTPS مجانية تتجدد وحدها (Caddy)، وجدار حماية، ونسخة احتياطية كل ليلة.

## ما تحتاجه

- **سيرفر VPS** بنظام **Ubuntu 24.04** (مثلاً Hostinger KVM 2). احتفظ بعنوان IP وكلمة سر root التي تعطيك إياها الشركة.
- **دومين** (مثلاً himma.fit).
- اختياري: حساب مجاني على **Brevo** لإرسال الإيميلات (روابط تغيير كلمة السر). يمكن إضافته لاحقاً.

## ١. اربط الدومين بالسيرفر

من لوحة الشركة التي اشتريت منها الدومين (أو Cloudflare)، افتح إعدادات DNS وأضف سجلّين:

| النوع | الاسم | القيمة |
|---|---|---|
| A | `@` | عنوان IP للسيرفر |
| A | `www` | عنوان IP للسيرفر |

إذا كنت تستعمل Cloudflare، اجعل السحابة **رمادية (DNS only)** في البداية. قد يأخذ السجل من دقائق إلى ساعة حتى يعمل.

## ٢. ادخل إلى السيرفر

من ويندوز افتح **PowerShell** واكتب (ضع عنوان سيرفرك):

</div>

```
ssh root@123.45.67.89
```

<div dir="rtl">

اكتب `yes` عند السؤال الأول، ثم كلمة سر root (لا تظهر الأحرف أثناء الكتابة، وهذا طبيعي). أو استعمل الطرفية (Terminal) الموجودة في لوحة Hostinger مباشرة.

## ٣. شغّل التجهيز

انسخ السطرين والصقهما في السيرفر:

</div>

```
git clone https://github.com/Ameen041/Gym-Management-System.git /opt/himma
bash /opt/himma/deploy/setup.sh
```

<div dir="rtl">

سيسألك:

1. **الدومين** بدون www، مثل `himma.fit`.
2. **إيميل الأدمن** الذي ستدخل به (وتصله تنبيهات الشهادة).
3. **كلمة سر الأدمن**: 10 أحرف على الأقل، مرتين.
4. **إعدادات الإيميل**: اضغط Enter لتتخطاها الآن، أو أدخل بيانات Brevo (في الأسفل).

بعدها يثبّت Docker ويبني المنصة ويشغّلها. أول مرة تأخذ بين 5 و10 دقائق. في النهاية يكتب لك **Himma is running** ورابط موقعك.

## ٤. بعد التشغيل

1. افتح `https://دومينك` وسجّل الدخول بإيميل الأدمن.
2. افتح **النظام** من القائمة: يجب أن تكون كل الأسطر خضراء. سطر الإيميل يبقى أحمر حتى تضبط Brevo، وسطر النسخة الاحتياطية حتى تمر أول ليلة (أو اضغط «نسخ احتياطي الآن»).
3. من **الإعدادات** أدخل حساب شام كاش الذي يدفع عليه المتدربون ونسبة العمولة.

إذا لم يعمل HTTPS فوراً فالسبب غالباً أن سجل الدومين لم يصل بعد. لا تفعل شيئاً: الشهادة تُطلب وحدها عندما يصبح الدومين جاهزاً.

## الإيميل عبر Brevo

1. أنشئ حساباً مجانياً على brevo.com (300 رسالة يومياً).
2. من **Senders, Domains & Dedicated IPs** أضف الإيميل الذي سترسل منه وأكّده.
3. من **SMTP & API** ثم **SMTP** انسخ: SMTP server و Login، وأنشئ **SMTP key**.
4. على السيرفر افتح ملف الإعدادات:

</div>

```
nano /opt/himma/deploy/.env
```

<div dir="rtl">

وعدّل هذه الأسطر (اترك علامتي ' حول القيم):

</div>

```
MAIL_MAILER=smtp
MAIL_HOST=smtp-relay.brevo.com
MAIL_PORT=587
MAIL_USERNAME='الـ Login من Brevo'
MAIL_PASSWORD='الـ SMTP key'
MAIL_FROM_ADDRESS='الإيميل الذي أكّدته'
```

<div dir="rtl">

احفظ بـ `Ctrl+O` ثم Enter، واخرج بـ `Ctrl+X`، ثم شغّل `himma restart`.

## الأوامر اليومية

| الأمر | ماذا يفعل |
|---|---|
| `himma update` | يجلب آخر نسخة من GitHub (فرع master) ويعيد التشغيل. البيانات تبقى كما هي |
| `himma status` | هل كل شيء يعمل؟ |
| `himma logs` | ما تكتبه المنصة الآن (`Ctrl+C` للخروج) |
| `himma backup` | نسخة احتياطية الآن، وتُنسخ كل النسخ إلى `/root/himma-backups` |
| `himma restart` | إعادة تشغيل، وقراءة أي تعديل في `deploy/.env` |

**التحديث:** ادمج التعديلات على GitHub أولاً، ثم ادخل إلى السيرفر وشغّل `himma update`.

## النسخ الاحتياطية

- المنصة تأخذ نسخة كل ليلة وتحتفظ بآخر 14 نسخة على السيرفر.
- هذا لا يكفي إذا تعطّل السيرفر نفسه، لذلك **نزّل نسخة كل أسبوع إلى جهازك**: من صفحة **النظام** في لوحة الأدمن، أو بعد `himma backup` بهذا الأمر من PowerShell على جهازك (يطبعه لك `himma backup` جاهزاً):

</div>

```
scp root@123.45.67.89:/root/himma-backups/himma-2026-11-01-030000.json.gz .
```

<div dir="rtl">

## إذا صار شيء

- **الموقع لا يفتح:** `himma status`. إذا كان شيء متوقفاً شغّل `himma start`، ثم انظر `himma logs`.
- **HTTPS لا يعمل:** تأكد أن سجلي A يشيران إلى عنوان السيرفر، وانظر `himma logs caddy`.
- **نسيت كلمة سر الأدمن:** صفحة «نسيت كلمة السر» (بعد ضبط الإيميل).
- **غيّرت شيئاً في `deploy/.env`:** شغّل `himma restart`.
- **تريد تشغيل التجهيز من جديد:** `bash /opt/himma/deploy/setup.sh` يحتفظ بإعداداتك ويشغّل المنصة فقط.

## Cloudflare (اختياري)

بعد أن يعمل الموقع على HTTPS، يمكنك تفعيل السحابة البرتقالية في Cloudflare لتسريع الملفات الثابتة. اجعل **SSL/TLS** على **Full (strict)**. المنصة تعرف عنوان الزائر الحقيقي خلف Cloudflare، فحدود محاولات الدخول تبقى لكل زائر وحده.

## ما الذي في هذا المجلد

| الملف | دوره |
|---|---|
| `setup.sh` | التجهيز لأول مرة: Docker، جدار الحماية، الأسئلة، التشغيل |
| `compose.yml` | ثلاث حاويات: المنصة، MySQL، و Caddy |
| `Caddyfile` | شهادة HTTPS وتحويل www والطلبات إلى المنصة |
| `himma` | الأوامر اليومية |
| `.env` | إعداداتك وكلمات السر (يُنشأ على السيرفر فقط، ولا يُرفع إلى GitHub) |
